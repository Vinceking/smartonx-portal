# SMART ON X — CUSTOMER ORDERING PORTAL
# Complete Build Specification v1.0 (Epic / Stories / Sprints)

**Owner:** Vinny King · **Staff stakeholder:** Rachelle (Smart On X)
**Target:** Replit Agent prototype, fully functional on mock data
**Architecture decision of record:** HubSpot is the LIVE system of record for CRM
entities (companies, locations, contacts, billing profiles) — the portal QUERIES
it at read time via a service layer. For the prototype, a "mock HubSpot" backing
store stands in behind identical function signatures. Shopify owns transactions.
The portal database holds ONLY auth, permissions, orders, and logs.

# ⛔ SECTION 0 — ANTI-VAPORWARE RULES (paste into EVERY Replit prompt)

Replit Agent tends to build beautiful non-functional shells. These rules are
non-negotiable and apply to every story:

```
FUNCTIONALITY RULES — VIOLATIONS = STORY REJECTED:
R1. Every button, link, and form in this spec MUST perform its described
    action against the database. No dead buttons, no alert('coming soon'),
    no console.log-only handlers, no href="#".
R2. No hardcoded display data in components. Every table, card, dropdown,
    and stat renders from a database query or the hubspot service layer.
    If seed data changes, the UI must change.
R3. All forms: server-side validation (client-side is a bonus, not a
    substitute). Invalid submits return field-level errors rendered inline.
R4. All role restrictions enforced SERVER-SIDE in the route/API handler
    (return 403 JSON + friendly UI state). Hiding a button is not security.
R5. Every list page has a real empty state ("No orders yet" + CTA) and a
    loading state. Verify empty states by testing with a fresh org.
R6. Every write operation must be verifiable: after submit, the new/changed
    record must appear in the relevant list AND in the database.
R7. Session auth on every /portal and /admin route. Manually hitting a URL
    while logged out redirects to the correct login page. Purchaser hitting
    an admin URL gets 403, not a broken page.
R8. Money stored as integer cents everywhere. Render with a single
    formatCurrency() helper. No floating point math on money.
R9. All timestamps stored UTC (timestamptz), rendered in America/Denver.
R10. Seed script must be idempotent (npm run seed wipes and rebuilds) and
     the README must list every demo credential.
R11. At the end of each sprint, run the sprint's QA CHECKLIST (included
     below) and fix failures before declaring done.
```

# SECTION 1 — EPIC DEFINITION

**EPIC:** B2B customer ordering portal for Smart On X that (a) authenticates
dentists / prosthodontists / lab staff independently of email address,
(b) lets them order products with pre-verified shipping/billing data resolved
live from HubSpot, (c) pushes orders to Shopify with canonical data + HubSpot
IDs attached, (d) writes a linked PO record back to HubSpot, and (e) gives
Smart On X staff (Rachelle) a God-mode console to onboard and manage every
organization, user, location, and billing profile.

**Problem being solved:** The standard Shopify↔HubSpot integration keys on
email. New or misspelled emails ("First St" vs "1st St", doctor's gmail vs
office email) create orphan contacts and orders that never associate to the
Organization or Location custom object. This portal makes the *account* the
identity anchor and makes every address a *selected, validated record* rather
than typed text.

**Personas:**
| Persona | Role key | Example |
|---|---|---|
| Front-desk / office manager who orders | purchaser | Maria at a 1-location practice |
| DSO regional manager | regional_admin | Covers 2 of 5 Summit Smiles locations |
| Practice owner / lab manager | org_admin | Dr. Chen; lab GM |
| Smart On X staff | staff (God mode) | Rachelle |

**Out of scope for this prototype (phase 2+):** real HubSpot/Shopify/USPS
credentials, real email sending, real payments, HubSpot-side workflow tasks,
two-way HubSpot webhooks, SSO.

## 3A. Portal-owned tables (Postgres via Drizzle)

```sql
-- ===== AUTH & PERMISSIONS =====
CREATE TABLE roles (
  id            serial PRIMARY KEY,
  key           text UNIQUE NOT NULL,          -- 'purchaser' | 'regional_admin' | 'org_admin'
  label         text NOT NULL,
  description   text NOT NULL
);

CREATE TABLE portal_users (
  id                   serial PRIMARY KEY,
  hubspot_contact_id   text NOT NULL,           -- pointer into HubSpot (mock: 'hs-c-###')
  hubspot_company_id   text NOT NULL,           -- pointer into HubSpot (mock: 'hs-o-###')
  username             text UNIQUE NOT NULL,    -- lowercase, 3-30 chars, [a-z0-9._-]
  password_hash        text NOT NULL,           -- bcrypt, cost 10
  role_id              int NOT NULL REFERENCES roles(id),
  must_change_password boolean NOT NULL DEFAULT false,
  is_active            boolean NOT NULL DEFAULT true,
  last_login_at        timestamptz,
  created_at           timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE user_location_access (            -- purchasers & regional_admins only
  id                  serial PRIMARY KEY,
  portal_user_id      int NOT NULL REFERENCES portal_users(id) ON DELETE CASCADE,
  hubspot_location_id text NOT NULL,            -- pointer into HubSpot location object
  can_order           boolean NOT NULL DEFAULT true,
  UNIQUE (portal_user_id, hubspot_location_id)
);
-- RULE: org_admins have implicit access to ALL company locations; no rows here.

CREATE TABLE password_reset_tokens (
  id             serial PRIMARY KEY,
  portal_user_id int NOT NULL REFERENCES portal_users(id) ON DELETE CASCADE,
  token          text UNIQUE NOT NULL,          -- 32-byte random hex
  expires_at     timestamptz NOT NULL,          -- now() + 1 hour
  used_at        timestamptz
);

CREATE TABLE admin_users (                     -- Smart On X staff (God mode)
  id            serial PRIMARY KEY,
  name          text NOT NULL,
  email         text UNIQUE NOT NULL,
  password_hash text NOT NULL,
  is_active     boolean NOT NULL DEFAULT true,
  last_login_at timestamptz
);

-- ===== COMMERCE =====
CREATE TABLE products (
  id                  serial PRIMARY KEY,
  sku                 text UNIQUE NOT NULL,
  shopify_product_id  text,                     -- null in mock
  shopify_variant_id  text,
  name                text NOT NULL,
  product_line        text NOT NULL,            -- 'Omnibut'|'Rapid Arches'|'Rapid Set Pickup Acrylic'|'SimpleTemp'|'Smart Denture Conversions'
  description         text NOT NULL,
  unit_price_cents    int NOT NULL CHECK (unit_price_cents >= 0),
  image_url           text NOT NULL,            -- placeholder images ok
  active              boolean NOT NULL DEFAULT true
);

CREATE TABLE orders (
  id                       serial PRIMARY KEY,
  order_number             text UNIQUE NOT NULL,       -- 'SOX-' + zero-padded seq, e.g. SOX-001042
  hubspot_company_id       text NOT NULL,
  hubspot_location_id      text NOT NULL,
  hubspot_contact_id       text NOT NULL,              -- contact of the placing user
  portal_user_id           int NOT NULL REFERENCES portal_users(id),
  placed_by_role           text NOT NULL,
  po_number                text NOT NULL,
  order_notes              text,
  -- SNAPSHOTS (immutable copies taken at submit time; NEVER re-resolved):
  ship_snapshot            jsonb NOT NULL,  -- {nickname,address1,address2,city,state,zip,phone}
  billing_snapshot         jsonb NOT NULL,  -- {profile_name,address1,address2,city,state,zip,ap_email,ap_phone}
  payment_terms_snapshot   text NOT NULL,   -- 'card_at_checkout' | 'net_terms'
  net_days_snapshot        int,
  payment_status           text NOT NULL,   -- 'paid' | 'terms_net'
  subtotal_cents           int NOT NULL,
  shipping_cents           int NOT NULL,    -- flat 1500; 0 when subtotal >= 50000
  total_cents              int NOT NULL,
  status                   text NOT NULL DEFAULT 'submitted',
                           -- 'submitted'|'processing'|'shipped'|'delivered'|'cancelled'
  shopify_order_id         text,            -- from mock shopify service
  shopify_order_number     text,            -- 'SX-#####'
  hubspot_po_id            text,            -- from mock hubspot PO create
  hubspot_po_status        text NOT NULL DEFAULT 'pending',  -- 'pending'|'synced'|'error'
  ordered_at               timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE order_items (
  id               serial PRIMARY KEY,
  order_id         int NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
  product_id       int NOT NULL REFERENCES products(id),
  sku_snapshot     text NOT NULL,
  name_snapshot    text NOT NULL,
  quantity         int NOT NULL CHECK (quantity > 0),
  unit_price_cents int NOT NULL,
  line_total_cents int NOT NULL
);

-- ===== WORKFLOW & LOGS =====
CREATE TABLE location_requests (
  id                   serial PRIMARY KEY,
  hubspot_company_id   text NOT NULL,
  requested_by_user_id int NOT NULL REFERENCES portal_users(id),
  nickname             text NOT NULL,
  address1             text NOT NULL,
  address2             text,
  city                 text NOT NULL,
  state                text NOT NULL,           -- 2-letter
  zip                  text NOT NULL,
  phone                text,
  validated            boolean NOT NULL DEFAULT false,
  place_id             text,
  status               text NOT NULL DEFAULT 'pending',  -- 'pending'|'approved'|'rejected'
  resolved_by          text,                    -- 'org_admin:{id}' or 'staff:{id}'
  resolved_at          timestamptz,
  created_at           timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE email_log (
  id          serial PRIMARY KEY,
  to_address  text NOT NULL,
  cc_address  text,
  subject     text NOT NULL,
  body_text   text NOT NULL,
  category    text NOT NULL,   -- 'location_request'|'welcome'|'password_reset'|'order_confirmation'|'username_reminder'
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE integration_log (
  id          serial PRIMARY KEY,
  order_id    int REFERENCES orders(id),
  system      text NOT NULL,     -- 'shopify' | 'hubspot'
  operation   text NOT NULL,     -- e.g. 'draftOrderCreate','po.create','company.create','location.create','contact.create','location.update'
  direction   text NOT NULL DEFAULT 'outbound',
  payload_json jsonb NOT NULL,   -- the EXACT real-API-shaped payload
  result_json  jsonb,            -- mock response incl. generated ids
  created_at  timestamptz NOT NULL DEFAULT now()
);
```

## 5.2 `/login`
Fields: "Username or email" (text, required) · Password (required, show/hide
toggle). Actions: **Log In** → POST /api/auth/login:
1. Normalize input to lowercase. If it contains "@": resolve via
   `hubspot.searchContactByEmail()` → find portal_user by hubspot_contact_id.
   Else match portal_users.username.
2. Verify bcrypt; check is_active (inactive → "This account is disabled.
   Contact your account administrator.").
3. Wrong creds → single generic error "Invalid credentials." (no user
   enumeration). Set session {userId, roleKey, hubspotContactId,
   hubspotCompanyId}; update last_login_at.
4. must_change_password=true → force redirect to /portal/change-password
   before anything else.
5. Else → /portal.
Links: "Forgot username?" · "Forgot password?".
**Demo panel** (collapsible): table of ALL demo logins from Section 4A with
role labels, + note "Staff console: /admin".
✅ QA: log in as `schen` via username, AND via `drchen.wasatch@gmail.com`

## 5.4 `/forgot-password` and `/reset-password`
- Forgot: username-or-email field → if matched, create password_reset_tokens

## 5.9 `/portal/order/new` — Wizard 🔒 (THE core flow)
Progress: ① Ship To ② Billing & PO ③ Products ④ Review [⑤ Payment if card].
State in client store; Back never loses data; direct URL to a later step
without prerequisites bounces to step 1.

**Step 1 — Ship To.** Selectable location cards (live from hubspot service,
role-filtered): nickname, full address, phone, "Default" + "✓ Verified"
badges. Radio-select + **Continue** (disabled until selected). If the user
has EXACTLY one permitted location: auto-select, render as confirmation card,
skip straight to step 2 with an "editing disabled — one location on file"
note. Link under grid: purchaser/regional_admin → "Need to ship somewhere
new? Request a location" (opens 5.11 request modal; order continues
meanwhile); org_admin → "Add a new location" (opens 5.13 add-location modal;
on save, new card appears immediately).

**Step 2 — Billing & PO.** Billing card auto-resolved from selected
location's billing_profile (live fetch): profile name, address, AP email,
terms line ("Net 30 — invoice to ap@…" or "Card payment at checkout").
If org has >1 profile AND user is org_admin/regional_admin: select-only
dropdown to switch profiles; purchasers see fixed card. **PO Number** text,
required, max 40 chars, prefilled suggestion = org's last PO +1 (e.g.
PO-2026-0418), editable. Optional Order Notes textarea (500 chars).
Continue validates PO non-empty.

**Step 3 — Products.** Collapsible sections per product line; search box
filters by name/SKU live. Each row: image thumb, name, SKU, unit price,
qty stepper (0–99, typed input allowed, invalid→1). **Cart summary** (right
rail desktop / sticky bottom bar mobile): line count, each item w/ qty ×
price, remove ✕, running subtotal, shipping preview ($15.00, FREE ≥ $500),
total. Continue requires ≥1 item. Reorder/Quick-Reorder entry lands here
preloaded.

**Step 4 — Review.** Read-only: ship card, billing card, PO + notes, items
table, totals. "Edit" links jump to each step. Submit button label depends
on terms: net_terms → **"Submit Order — Net {n} Terms"**; card → **"Continue
to Payment"**.

**Step 5 — Payment (card orgs only).** Big amber banner "DEMO — no real
charge". Fields: name on card, card number (any 13–19 digits), MM/YY, CVC —
format-validated only. "Pay ${total} & Submit".

**Submit → POST /api/orders (single transaction):**
1. Server re-validates: role/location permission, products active, qty>0,
   PO present.
2. Fresh (cache-bypassed) `hubspot.getLocation` + `getBillingProfile` →
   build snapshots.
3. Recompute all money server-side from DB prices (ignore client totals).
4. Insert order (payment_status: net→'terms_net', card→'paid') + items;
   generate order_number.
5. `shopify.createDraftOrder(order)` — mock builds REAL Admin GraphQL
   `draftOrderCreate` payload: lineItems (variantId/sku/qty), shippingAddress,
   billingAddress, email, note, customAttributes [{po_number},
   {hubspot_company_id},{hubspot_location_id},{hubspot_contact_id}], tags
   ["portal-order"], paymentTerms when net — logs to integration_log, returns
   {id:'gid://mock/…', order_number:'SX-#####'} → stored on order.
6. `hubspot.createPurchaseOrder(order, shopifyResult)` — CRM v3 create
   payload with properties {po_number, shopify_order_id,
   shopify_order_number, amount, order_date} + v4 associations to contact,
   company, location → integration_log; store hubspot_po_id, status 'synced'.
7. `mailer.orderConfirmation()` → email_log to user's primary email, CC
   ap_email when net_terms.
8. Return {orderId} → redirect `/portal/orders/{id}?placed=1`.
✅ QA: verify AFTER one order: orders row + items rows + 2 integration_log
rows + 1 email_log row all exist; totals recomputed correctly server-side.
